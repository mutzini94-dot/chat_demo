01 · 시스템 개요 System Overview

채팅은 어떤 축으로 구성되는가

치지직 채팅은 실시간 라이브 채팅과 다시보기(VOD) 채팅 두 재생 모드를 갖고, 시청은 비로그인으로 가능하되 작성은 로그인이 전제다. 실시간 스트림은 소켓 기반 채널로 유지되며, 후원·구독·모더레이션이 채팅 레이어 위에 얹힌다.

Client · 진입 모드
  • 라이브 채팅플레이어 우측 도킹 / 전체화면 오버레이
  • 채팅 팝업(별도 창)독립 창으로 분리, 방송용 세컨드 모니터
  • 다시보기 채팅VOD 타임라인 동기화 재생
  • 모바일 채팅세로 오버레이 / 가로 반투명
Realtime · 전송 계층
  • 실시간 채널WebSocket 상시 연결, 메시지 브로드캐스트
  • 세션/토큰채널ID + 사용자 세션으로 접속 인증
  • 재연결·백오프네트워크 단절 시 자동 재접속
  • 시청자/참여 수주기적 폴링 또는 이벤트 갱신
Overlay · 상위 기능
  • 후원(치즈)채팅·영상·미션 후원의 채팅 노출
  • 구독뱃지 · 전용 이모티콘 · 전용 채팅
  • 모더레이션매니저 · 제한 · 삭제 · 금칙어 · 클린봇
  • 알림/시스템 메시지입장·팔로우·구독·공지 고정
R1

역할 모델

일반 시청자 · 팔로워 · 구독자 · 채팅 매니저 · 스트리머(방송인). 권한과 뱃지, 채팅 제한 적용 범위가 역할에 따라 달라진다.

R2

참여 게이트

로그인 여부, 팔로우 경과 시간, 구독 여부, 슬로우 모드, 활동 제한 상태가 순차적으로 "전송 가능 여부"를 결정한다.

R3

수익 결합

채팅은 후원(치즈)·구독의 노출 무대다. 텍스트 채팅과 유료 이벤트가 같은 타임라인에서 시각적으로 차등 표시된다.

건강한 채팅을 위한 통제 장치

스트리머와 채팅 매니저가 실시간으로 채팅을 통제한다. 참여 제한(팔로워/구독자 전용), 슬로우 모드, 활동 제한(임시·영구), 메시지 삭제, 금칙어, 클린봇 자동 필터가 핵심 축이다.

M1

매니저 위임

스트리머가 특정 사용자를 채팅 매니저로 지정/해제. 매니저는 제한·삭제 권한을 위임받는다.

M2

클린봇

욕설·스팸·부적절 채팅을 자동 감지해 블라인드. 시청자는 개인 화면에서 클린봇 필터 on/off 가능.

M3

참여 게이트

팔로우 후 경과 시간·구독 여부 조건으로 신규 계정/뜨내기 도배를 억제한다.

10 · 상태 & 예외 처리 States & Edge Cases

정상 흐름 밖에서 벌어지는 일

실시간 시스템은 연결 단절·권한 변화·제한 상태를 사용자에게 명확히 알려야 한다. 아래 상태별 UX를 정의한다.

  • 비로그인채팅 열람 가능, 입력창 잠금 + 로그인 유도 문구.
  • 연결 끊김소켓 단절 감지 시 "재연결 중" 표시, 자동 백오프 재접속. 복구 후 정상화.
  • 팔로워 전용조건 미충족 시 입력창에 "팔로우(및 경과 시간) 후 참여 가능" 안내.
  • 구독자 전용비구독자 전송 차단 + 구독 유도 안내.
  • 슬로우 모드남은 대기 시간 카운트다운, 만료 후 전송 재허용.
  • 활동 제한임시(남은 시간)·영구 제한 시 사유·기간 안내, 입력 차단.
  • 메시지 차단금칙어/클린봇 걸림 시 미전송 또는 블라인드 처리 안내.
  • 방송 종료라이브 종료 시 실시간 채팅 종료 안내, 다시보기 채팅으로 전환.
  • 빈/저활성 채팅메시지 없음 상태의 플레이스홀더, 첫 채팅 유도.

Performance

전송~수신 체감 지연 최소화(수백 ms 목표), 폭주 시에도 UI 프레임 유지(가상 스크롤·배치 렌더).

Scalability
동시 접속 확장

인기 방송의 수만~수십만 동시 시청/채팅을 감당하는 채널 샤딩·팬아웃 구조.

Reliability
연결 복원력

단절 자동 재연결·백오프, 재접속 후 최근 맥락 표시. 메시지 유실 최소화.

Safety
실시간 안전성

클린봇·금칙어의 즉시성, 제한 조치의 전파 일관성, 미성년 보호 정책 준수.

Compatibility
멀티 플랫폼

PC 웹·모바일 웹/앱, 전체화면·팝업·세로/가로 레이아웃 일관 동작.

Accessibility
가독·접근성

글자 크기·명암, 색상만이 아닌 뱃지 텍스트 병기, 키보드 전송 지원.

12 · 자체 서비스 적용 시사점 Implications

우리 제품에 옮길 때

본 프로젝트(스트리밍/OBS·열혈톡·후원 정산)와 맞물리는 관점에서, 치지직 채팅에서 우선 벤치마킹할 지점을 정리한다.

1
수익-채팅 결합 모델

후원(치즈)의 금액대별 차등 노출은 "화력"을 시각화한다. 자체 후원 정산 ERD와 채팅 노출 규칙을 연결해 설계하라.

2
참여 게이트 3단

로그인 → 팔로워(경과시간) → 구독의 단계별 게이트는 도배·어뷰징 억제의 핵심. MVP부터 슬로우모드+팔로워전용은 포함 권장.

3
매니저 위임 + 클린봇

사람(매니저)과 자동 필터(클린봇)의 2중 모더레이션이 표준. 운영 인력 없이도 자동 필터 강도 설정이 필수.

4
다시보기 채팅 동기화

VOD 타임라인-채팅 동기는 콘텐츠 재사용 가치를 높인다. 채팅 로그를 타임스탬프와 함께 보존하는 저장 설계 필요.

✅

다음 단계 권장

실서비스 반영 전, 실제 라이브/스튜디오 화면에서 정량 값을 확정하라 — ① 메시지 최대 글자 수, ② 슬로우 모드 단위·기본값, ③ 후원 금액 구간과 노출 시간, ④ 팔로워 전용 경과 시간 옵션, ⑤ 표시 버퍼 상한. 확정 후 각 요건의 "재검증 필요" 표기를 제거하면 개발 착수용 SRS로 승격된다.
